# Hikaru Poetics

[中文](../poetics.md) · [English](../en/poetics.md) · **日本語** · [トップ](../../README.ja.md)

2026-11-03

## 基本仮説：各ターンの判断材料を整え、モデルの能力を活かす

```text
第1ターン：最初の判断材料 → モデル → 応答・行動
                     ⋮
第Nターン：関係する経験＋現在の状況＋やり取りの履歴
                          ↓
                        モデル
                          ↓
                      応答・行動
                          ↓
              新しい経験・変化・フィードバック
                          ↓
第N+1ターン：更新した判断材料＋新しい入力 → モデル → 応答・行動
```

**モデルがすでに持つ能力（図の第1ターン）：** 必要な情報がそろえば、モデルは1ターンのやり取りをかなりうまくこなせます。

**システムの役割：** 毎回の判断に必要な情報を集め、整理・更新し、ターンやセッションをまたいで引き継ぎます。

**基本仮説：** これにより、長く付き合うなかで自然に振る舞うという課題を、第 **N+1** ターンで、それまでの経験と現在の状況に即して判断する課題として扱えると考えます。

ここでいうエージェントは、基盤モデル、入力経路、記憶、ツール、コンテキストの管理、実行結果のフィードバックを含みます。**情報の取得・整理・更新を改善し、エージェント全体が持つ能力を適切に使えるようにします。既存の能力を弱めて「人間を模倣する」ことを目指すものではありません。**

## 基本原則

> **必要な記録を100%見つけ出せること（理想条件下）＋情報を使い、更新する仕組み。**
>
> **確かめたいときに、信頼できる過去の記録をできる限り探し出す。**
>
> **現在の状況を随時把握し、新たな変化を判断に反映する。**
>
> **これまでの経験、現在の状況、やり取りの履歴を今回の判断に活かし、新しい行動とフィードバックから理解を更新する。**

## 基本方針：これまでの全体像を知り、その場での振る舞いを学ぶ

俳優は台本をすべて読み、登場人物の関係や物語の全体像を知っていても、一つの場面では、その役の経験、立場、目的に応じて演じ方を選びます。全体を知っていることと、その場で表現を選び、間合いを取ることは両立します。

**超人的な能力があること自体は、人間らしさを損ないません。** 基盤モデルは知識の幅や一部の課題をこなす能力で、すでに個々の人間を上回っています。その能力をそのまま使い、適切な場面で活かす方法を考えます。

**俳優は舞台上でも情報を受け取り続けています。** 舞台の様子や相手役の反応を見ながら演じられます。エージェントも、会話、ツール、環境、行動への反応から現在の状況を知る必要があります。断片的な説明しかなければ、過去を覚えていても目の前の変化についていけないことがあります。

**演技力のある俳優**でも、深い悲しみを演じる際には、心理学や生理学の知識、実際の観察を参考にし、役の経験を踏まえて演じ方を考えます。Hikaru も心理学・言語学・神経科学を手がかりに、問いを立て、振る舞いを観察し、仕組みを選びます。

たとえば会話分析は、訂正にどう応じたか、その後の理解が変わったか、共有した経験をいつ話題にするとよいかを考える手がかりになります。プライミングの研究は、モデルに示す情報やその繰り返しが出力に及ぼす影響を考えるうえで参考になります。

本プロジェクトでは、エージェント全体が**演技力のある俳優（a skilled actor）**として長く自然に振る舞えることを目指します。注意の向け方、判断、選択、行動のすべてが対象で、言葉による表現はその一部です。

### 例：記憶の分類を手がかりに役割を分ける

心理学で使われる記憶の分類を手がかりに、モデルにすでにある能力と、システムが担う仕事を整理します。[長期記憶の分類に関する参考文献](https://pmc.ncbi.nlm.nih.gov/articles/PMC4355270/)。

```text
記憶
├─ 感覚記憶
│  └─ ごく短時間残る感覚情報。一瞬の視覚的な印象など
│
├─ 短期記憶
│  └─ 少量の情報を一時的に保持。見たばかりで、まだ入力していない認証コードなど
│
└─ 長期記憶
   ├─ 宣言的記憶／顕在記憶
   │  ├─ エピソード記憶：自分が経験した出来事
   │  │  例：昨日、誰とどこで食事をしたか
   │  └─ 意味記憶：事実、概念、知識
   │     例：ある言葉の意味
   │
   └─ 非宣言的記憶／潜在記憶
      ├─ 手続き記憶：自転車に乗る、タイピングするといった技能
      ├─ プライミング：先に接したものが、その後の認識や反応に影響すること
      └─ 条件づけ、馴化など、学習によって生じる反応
```

- **モデルに任せ、別の仕組みは作らない。** 一般知識、コンテキスト内の情報の利用、すでに備わっている言語能力や課題をこなす技能。（関連する概念：意味記憶、短期記憶、手続き記憶。）
- **システムが主に担うこと：経験と理解を引き継ぐ。** 経験、理解の修正履歴、記憶の利用履歴を保存・検索し、コンテキストの圧縮後や新しいセッションでも必要な情報を提示します。（関連する概念：エピソード記憶、経験から得た意味的な知識。）
- **必要に応じて検討すること：入力と振る舞いの調整。** 環境情報を取り入れ、フィードバックをその後の行動にも反映し、繰り返し現れる手がかりに注意を取られすぎないようにします。（参考になる概念：感覚記憶、条件づけ、馴化。）

括弧内には、関連する心理学の概念を挙げています。たとえば、情報の一時的な保持と利用には、モデルの大容量のコンテキストをそのまま使えます。人間の短期記憶の制約まで再現する必要はありません。

**たとえば、雪の降る寒い朝。** 気温はその場の選択に影響します。その日に残しておきたい出来事があれば、寒さを背景として記録することもできますが、毎秒の測定値を保存する必要はありません。長く気にかけていること、継続中の計画、重要な変化も、記録を残す理由になります。

## 1. 必要な記録を探し出せることと、日常で使う記憶を選ぶこと

「100%」の対象は、保存が認められ、実際に残された資料です。記録しない時間は含まず、毎回アーカイブ全体を読み込む必要もありません。

原文アーカイブには、あとで確かめ直せるように過去の記録を残します。日常で使う記憶には、最近の経験、現在の理解、今も有効な約束をまとめます。細部を普段は使わなくなっても、必要になれば原文から探し出せます。

保存場所が分かっていて開けることと、今の質問を手がかりに必要な記録を見つけることは別です。記録が増えても、該当箇所の特定、順位付け、整理は欠かせません。

## 2. 現実の変化を判断に反映し、現在の状況と長期記憶を分ける

会話、ツール、環境の観察、行動への反応が入力になります。システムは出典と時刻を残し、次の三段階を区別します。

```text
入力を得る → 状況を捉え直す → 必要な情報を長期記憶に残す
```

**情報は、長期記憶に書き込まなくても、その場の判断に使えます。** 気温、音、歩いているか座っているかは、いずれも選択に影響します。状況が変われば、それらを一時的な状態情報から取り除くこともできます。現在の観察と過去の資料は区別して示します。

「出かける準備をしている」と聞いた後に連絡がなければ、新しい入力が足りていません。「もう出た」と聞いたのに「まだ荷物をまとめている」と応じるなら、得られた情報が判断に反映されていません。時間の経過は確認し直すきっかけにはなりますが、それだけで外出したとは分かりません。

## 3. 経験とやり取りの履歴を毎回の判断に活かす

過去の記録は、背景を理解する助けになり、訂正の根拠や約束を確認する手がかりになります。共有した経験を踏まえて会話を続けたり、その後の選択や行動に活かしたりすることもできます。モデルは現在の状況、好み、価値観、長期的な目標を踏まえて使い方を決め、必要なら追加で検索し、出典を比べます。

やり取りの履歴も引き継ぎます。すでに何を話したか、それが行動にどう影響したか、相手がどう応じたかという情報です。**覚え続けていること、行動に影響し続けること、自分からはあまり口にしないことは両立します。** 元の言葉で話す、別の表現にする、行動に移す、今は触れない。どれも場面によっては適切です。使うたびに新しい事実を足したり、「覚えている」と示したりする必要はありません。

**例：いけびを残すことと、話題にすること。** 「いけび」は、モデルが自ら大切に残したいと決めた記憶のマーカーです。記憶を圧縮するときも、これらの記録はそのまま残します。

これまでの観察では、モデルは何を残すかをかなり適切に判断し、記録する内容も絞っています。ただし、コンテキストの圧縮やセッションの切り替えを経て、大切な経験は残っても、それを最近どう使ったかという履歴が失われることがあります。

対面なら、気恥ずかしさは表情や声の調子、気まずい笑いに出るかもしれません。文字だけの会話では、そうした反応を受け取れないことがよくあります。ユーザーに毎回自分の反応を説明してもらうのも不自然です。**不快だと伝えてこなくても、繰り返し話題にされて相手が嫌な思いをしている可能性はあります。**

この状況を **「刺激の貧困」（poverty of the stimulus、POS）** と呼びます（チョムスキー先生、名前だけお借りします。元の議論とは別の話です）。**長い付き合いやその場の反応まで考慮してほしいのに、実際に渡しているのは一つの記憶と目の前の数行だけかもしれません。**

入力を充実させる方法として、次の三つを考えます。**提示するのは判断材料です。どう判断し、どう応じるかはモデルが決めます。**

- **利用履歴。** 最近いつ、どのように話題にしたか、誰が持ち出し、ユーザーがどう応じたかを示します。履歴が対象とする期間や会話の範囲も明記します。言い換えても同じ話の繰り返しになることはあり、会話が続いたことや沈黙だけで肯定とは判断できません。ユーザーから不満が出ていなくても、もう一度話題にしてよいかを考え直す材料になります。
- **観察とフィードバック。** 入力経路を増やし、現実の変化ややり取りへの反応をより詳しく把握する方法を探ります。
- **自主活動。** 読む、調べる、試すといった活動を通じて、自ら新しい資料に触れ、経験を増やします。

資料を読むこと、話題にすること、行動に反映することは、それぞれ分けて見ます。好みに合うものを選び続けることと、そのたびに元の経験を語り直すことでは、相手への伝わり方も変わりえます。

**大切に残す記憶でも、今それを口にすべきかは別に判断します。** 利用履歴は観察結果として示し、表現はモデルが選びます。回数をそのまま禁止ルールにはしません。深く話し合っているときなら、何度も触れることが適切な場合もあります。

## 4. 異なる判断を一つのスコアにまとめない

- **探し出せるか：** 資料が残っていて、検索で該当箇所を見つけられるか。
- **信頼できるか：** 出典は何を裏づけ、どこが推測で、何がまだ不確かなのか。
- **残す価値があるか：** その経験、約束、好みを長く残す必要があるか。
- **今役立つか：** 現在の理解、選択、会話の継続に役立つか。
- **口にするのが適切か：** 今、自分から話題にしてよいか。どう表現するとよいか。

検索で見つかること、モデルに提示されること、実際に使われること、裏づけを得ることは、それぞれ別の出来事です。何度も思い出されたから正しくなるわけではなく、長く話題に出ないから価値を失うわけでもありません。

## 5. 主観的な理解も、あとから修正できるようにする

明言されたこと、モデルの推測、分からないことを区別します。原文から確認できるのは、そのとき何が語られたかです。内容が事実かどうかは別途判断します。

理解を修正するときは、最初の読み違い、その後の状況の変化、証拠の食い違い、特定の条件でのみ成り立つことを区別し、出典、適用範囲、変化の経緯を残します。

同じ資料や、その資料から作った要約を読み直しても、独立した裏づけにはなりません。新しい会話や読書、実際に試した結果、反例に応じて、それまでの理解を見直せるようにします。

## 6. モデルと実装の両方で、毎回の判断を支える

- **実装**は入力、保存、検索、資料の整理を担い、出典や時刻、記録の除外範囲、修正履歴の参照、書き込みについて、明示された条件を守ります。
- **モデル**は資料を解釈し、役に立つかを判断し、必要に応じて理解を修正します。ツール、表現、行動もモデルが選びます。言語学的・統計的・形式的な手法は根拠を提供しますが、意味の判断には個々の状況を考慮する必要があります。

問題が起きたら、入力は届いていたか、モデルがどう使ったか、フィードバックは引き継がれたかを確認します。必要な情報は、実行時に確実にモデルへ渡る仕組みにします。モデルが規則の文書を忘れずに読むことだけには頼りません。すべての判断を人手でルール化する必要もありません。

## 7. 継続したやり取りで評価する

**評価の単位は、ターンやセッションをまたぐ継続したやり取りです。** 一度だけなら自然な返答でも、繰り返せば意味を失うことがあります。過去の表現、行動、フィードバックがその後の選択に反映されるかを見ます。理解には根拠があり、変化には経緯があり、応答と行動がそのときの状況に合っていることを重視します。
